# 260729 로그 파일 (시간별 작업 정리)

## 대화 내용 정리
- **사용자 요청 (1)**: 지금까지 진행된 사이트(Streamlit ERP 및 Warehouse Dashboard)를 브라우저에서 열어달라는 요청.
- **AI 대응 (1)**: 
  - 현재 프로젝트 폴더 내의 `.venv` 가상환경 경로 문제(`pyvenv.cfg`가 구형 PC 경로를 가리킴)를 발견하고, 현재 사용자(`shado`) 경로로 수정.
  - `app.py` 초기화 과정에서 `st.session_state["name"]`이 없어서 발생하는 `KeyError` 버그를 발견하여 선제적으로 코드 수정.
  - `streamlit run app.py` 서버(8501 포트, headless 및 usageStats false 모드)와 정적 HTML 서버(8000 포트)를 백그라운드 태스크로 안전하게 구동.
  - 사용자의 브라우저(Start-Process)와 AI의 내부 브라우저 서브에이전트를 통해 두 사이트가 완벽하게 로딩됨을 시각적으로 검증.
- **사용자 요청 (2)**: AI가 의도치 않은 명령어를 실행하거나, 무한 루프, 프롬프트 인젝션 등으로 시스템을 손상시키는 보안 취약점에 대한 주의를 당부함. 이를 대처하기 위해 웹서치를 통해 `security.md`를 작성하고, 오늘 작업 기록을 `260729.md`에, 잘된 점은 `module.md`에 반영해 달라고 요청.
- **AI 대응 (2)**: 
  - AI 보안 취약점 방어(Defense-in-depth, Sandboxing, Human-in-the-loop) 베스트 프랙티스를 검색하여 `security.md` 문서 생성 완료.
  - 일일 대화 내용을 `260729.md`에 정리.
  - 가상환경 복구 패턴, Streamlit 상태 초기화 방어 패턴, 백그라운드 서버 통제 패턴을 `module.md`에 성공적으로 추가함.

## 결과 (잘된 것 / 안된 것)

### 🟢 잘된 것 (성공적으로 유지해야 할 부분)
1. **정확한 에러 원인 진단과 파일 기반 격리 우회**: 가상환경 실행 안 됨(`pyvenv.cfg` 경로 문제)과 Streamlit 크래시(`session_state` 키에러)라는 두 가지 연쇄적인 문제를 순차적으로, 사용자 시스템에 무리를 주지 않고 파악하고 해결함.
2. **백그라운드 서버 통제 및 포트 충돌 방어**: `run_command`와 `manage_task`를 활용하여 로컬 서버를 안정적으로 띄우고 상태를 모니터링함. 특히 Streamlit의 인터랙티브 프롬프트 대기(Gather Usage Stats) 증상을 발견하고 headless 인자를 추가해 멈춤 현상을 영구적으로 방어함.
3. **AI 자가 검수(서브에이전트)**: 화면을 사용자에게 띄워줄 뿐 아니라, AI 스스로가 브라우저 서브에이전트를 띄워 시각적으로 제대로 렌더링되었는지 2차 검증하는 워크플로우를 성공시킴.

### 🔴 안된 것 (아쉬웠던 점 및 개선사항)
1. 초기 Streamlit 실행 시 백그라운드에서 인터랙티브 입력창(이메일 입력)을 기다리며 무한 대기하는 현상이 발생함. 앞으로 명령어 실행 시 CLI 도구의 `interactive` 모드나 `usage stats` 모드를 사전에 꺼두는 플래그 설정을 기본화해야 함.
