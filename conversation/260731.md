# 260731 로그 파일 (시간별 작업 정리)

## 대화 내용 정리
- **사용자 요청 (1)**: 어제(29일)까지 만든 두 개의 사이트(Streamlit ERP 및 Warehouse HTML 대시보드)를 직접 브라우저에서 열어달라는 요청.
- **AI 대응 (1)**: 
  - 백그라운드 태스크 통제를 통해 `localhost:8501`과 `localhost:8000` 로컬 웹 서버 두 대를 성공적으로 기동시킴.
  - 브라우저 서브에이전트를 동원하여 양쪽 포트의 화면 렌더링이 성공적으로 이루어지는지 AI 자가 시각 검수를 완료한 뒤, 윈도우 PowerShell의 `Start-Process` 명령어를 통해 사용자 컴퓨터의 기본 웹 브라우저 창을 띄워 시각적으로 결과물을 제공함.

- **사용자 요청 (2)**: 
  - 직원 개인별로 매일/매주/매월/분기별 자신의 스케줄을 등록하고 스스로 완료 여부를 체크하여 업무 누락을 막을 수 있는 체크리스트 기능 추가 요청.
  - 최신 정보를 웹서치하여 `security.md`를 업데이트하고, 오늘 작업 내용 중 잘된 것을 `module.md`와 `260731.md`에 유지보수 문서로 남길 것을 지시함.
- **AI 대응 (2)**: 
  - OWASP 2024~2026 기반 웹 애플리케이션 보안 트렌드와 AI 코딩 보안 가이드를 웹 검색으로 습득하고 `security.md` 파일에 완벽 반영함.
  - `db.py`에 반복 업무 스케줄(tasks)을 저장하고 관리하는 CRUD 함수를 추가함(Firebase 및 Mock DB 양립형).
  - `views/schedule.py`라는 새로운 UI 페이지를 생성하고, `app.py` 사이드바의 네비게이션(st.Page)에 추가하여 로그인한 누구나 자신의 스케줄을 보고 토글(체크)할 수 있도록 시스템을 확장함.
  - 다중 백그라운드 서버 구동 및 에이전트 자가 검수 워크플로우를 `module.md`에 신규 등재하여 아키텍처 노하우를 영구 보존함.

## 결과 (잘된 것 / 안된 것)

### 🟢 잘된 것 (성공적으로 유지해야 할 부분)
1. **AI 에이전트 브라우저 자가 검수 기능 확립**: 단순히 파이썬 명령어로 웹 서버를 띄우고 "포트가 열렸다"고 가정하는 대신, AI가 직접 브라우저 서브에이전트에게 지시하여 캡처(스크린샷)본을 눈으로 확인함으로써, 백그라운드 프로세스가 완벽하게 살아있음을 검증하는 Human-in-the-Loop 대체 기술을 실증함.
2. **보안 문서 라이브 업데이트**: 단순한 코드 짜기를 넘어, 외부 웹 서치 도구를 동원해 2026년 기준의 보안 트렌드(Streamlit Pickle 주의, AI 샌드박싱 등)를 스스로 파악하여 `security.md`를 능동적으로 보완함.
3. **업무 스케줄러의 매끄러운 이식**: 기존의 재고 실사 중심이었던 ERP 앱에 "개인별 반복 할 일"이라는 새로운 도메인을 덧붙였음에도, 기존의 `shared_state.json` 폴백 로직 패턴을 똑같이 적용하여 Firebase 없이도 에러 없이 구동되도록 유연성을 극대화함.

### 🔴 안된 것 (아쉬웠던 점 및 개선사항)
- 개인 스케줄러 화면(`schedule.py`)에서 캘린더 위젯과 연동하여 '과거 날짜'의 완료 여부를 추적하거나 '관리자'가 팀원의 업무 완료율 통계를 보는 기능까지는 이번 페이즈에서 개발되지 않음. 향후 필요에 따라 단순 체크리스트에서 고도화된 스케줄러로 확장이 필요할 수 있음.
